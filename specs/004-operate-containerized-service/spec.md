# 004 · Operate the containerized service

## Outcome and relationship

Preserve the verified 001–003 counting and resource contracts and make the
compiled service understandable to operators, reviewers and future contributors.
This completes the assignment's operational packaging and portable verification.
It adds no durable media, patient/account model, database or external service.

## Acceptance

| ID  | Observable requirement                                                                                                                                                                                                                                                                                                                                                                             |
| --- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| O01 | Resolve immutable configuration at startup from HOST, PORT, MAX_FILE_BYTES, MAX_UPLOADS, REQUEST_TIMEOUT_MS, SHUTDOWN_GRACE_MS, UPLOAD_TEMP_DIR and LOG_LEVEL. Validate decimal integers/ranges and safe path/log-level values without echoing supplied secrets. Application/domain code does not read process.env.                                                                                |
| O02 | Default host is 127.0.0.1, port 3000, upload policy remains four/100 MiB/30 seconds, and shutdown grace is ten seconds. Port zero is allowed for isolated server tests; an external health probe requires a fixed nonzero port. The image binds 0.0.0.0.                                                                                                                                           |
| O03 | Startup must actually create, write and remove a private probe file before listening. GET /health/live returns 200 with `{"status":"ok"}`; GET /health/ready returns 200 with `{"status":"ready"}` only while admission is open and storage probing succeeds, otherwise 503 with `{"status":"not-ready"}`. Saturation alone does not fail readiness; restored storage can recover without restart. |
| O04 | Logs use generated correlation IDs, fixed event/route/category values and bounded typed operational fields. Do not include upload bytes, filenames, headers, raw URLs/queries, filesystem paths or arbitrary exception/message text, including at trace level. Unexpected upload/disposal failures remain observable even after an earlier response.                                               |
| O05 | SIGINT/SIGTERM begin one shutdown, stop admission and drain actual owned work. After grace, cancel via closed connections; allow one further second for settlement. Exit zero when owned work settles, including after cancellation, and nonzero on failure or the final bound. Repeated signals do not restart the grace period.                                                                  |
| O06 | The compiled healthcheck uses Node HTTP with an absolute two-second deadline and silent exit zero/one. Reject invalid/zero ports, refused connections, non-ready responses and trickling/stalled responses. Wildcard bind addresses map to loopback for the probe.                                                                                                                                 |
| O07 | Compiled-process tests run from an unrelated directory containing spaces and exercise the supplied sample, probes, startup errors, trace privacy, real malformed multipart traffic, graceful/forced shutdown and a final bound with deliberately unsettled disposal. Platform-specific signal checks are labelled accurately.                                                                      |
| O08 | Provide a digest-pinned Linux image with compiled JavaScript, production dependencies and package.json as its application payload. Run as node:node with root-owned code. Supply a TypeScript smoke command that builds/runs the real image, probes it, uploads the original sample for 6090, checks disposal and verifies clean stop.                                                             |
| O09 | The documented/smoke deployment policy uses a read-only root, bounded writable temporary storage, init, dropped capabilities/no new privileges and explicit CPU, memory, PID and stop limits. Explain tmpfs memory accounting and size local admission/file policy together with container resources. Replicas need no shared files or locks.                                                      |
| O10 | Configure pinned-action CI for the full gate on native Linux, macOS and Windows, plus a Linux container job and useful test reports. Keep all executable project source/tests/scripts in TypeScript and maintain existing strict checks, fixture identities and official Lean provenance.                                                                                                          |
| O11 | Complete README, architecture/domain/extension guidance, MP3 explanation, testing, operations and development instructions with explicit platform commands. Describe a small team adoption/measurement and human-ownership process without inventing adoption, delivery improvement, permission enforcement or execution evidence.                                                                 |
| O12 | Preserve all completed feature evidence and actual sequential history. Run the final gate from a clean revision and again from the packaged repository; record actual results, review dispositions and unavailable Docker/native/hosted checks separately from configured checks.                                                                                                                  |

Tests assert the exact response objects. Trusted ingress owns TLS, authentication, total transport limits
and fleet/tenant quotas. Structural counting remains separate from decoding,
transcription and persistent ingestion workflows. No configuration file proves
that Docker, a native platform or hosted protection has actually run.
